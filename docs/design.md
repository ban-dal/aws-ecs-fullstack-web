# 디자인 기준

## 첫 화면

홈은 요청 단위의 인프라 관측 대시보드다. 운영자가 먼저 현재 접속 주소·프로토콜·응답 인스턴스와 경로 확인 상태를 읽고, 아래에서 도메인 → ALB → ECS 태스크 → EC2 호스트의 근거를 확인한다. 이어서 1회 또는 8회 요청을 보내 관측된 호스트와 최근 요청 기록을 비교한다.

왼쪽 메뉴는 개요·요청 경로·요청 기록의 화면 내 이동만 제공한다. 상단에는 마지막 관측 시각을 UTC로 표시한다. 숫자와 호스트 ID는 같은 자리에 정렬하고, 인스턴스·태스크 ID와 시각에만 고정폭 글꼴을 쓴다. 좁은 화면에서는 메뉴를 가로 탐색으로 바꾸고 요약과 근거 영역을 한 열로 배치한다.

## 표현 원칙

- 한국어로 상태와 행동을 명확하게 적는다. 환경 이름과 AWS 고유명사는 원래 표기를 쓴다.
- 확인 상태는 색과 함께 `관측됨`·`미확인` 텍스트로 표시한다. 로컬에서는 운영 메타데이터를 확인할 수 없다고 알린다.
- 각 상태에는 관측 근거를 둔다. 헤더의 존재는 그 요청의 흔적이며, 인스턴스 표본을 전체 서비스의 정상 상태로 표현하지 않는다.
- 표는 정확한 기록을 확인하는 용도다. 시각, 응답 인스턴스, 가용 영역, ECS 태스크를 한 행에서 비교한다.
- 명확한 글자 위계와 정렬, 제한된 상태색, 충분한 여백을 사용한다. 장식용 그라디언트·아이콘·반복 카드는 쓰지 않는다. [Vercel design.md](https://vercel.com/design.md)의 정보 위계와 근거 중심 표현을 참고하되 프로젝트의 제품 화면과 브랜드를 유지한다.
- 키보드 포커스, 본문 바로가기, 의미 있는 제목 순서, 표 머리글, 상태 알림을 제공한다. 터치 버튼은 충분한 높이를 유지한다.

## 관측 상태

첫 페이지 요청 한 건이 초기값이다. 사용자가 검사를 실행하면 `/api/backend`에 새 요청을 보내 최근 12건만 브라우저 메모리에 유지한다. 요청 실패는 현재 표본을 유지한 채 오류를 표시한다. 호스트 정보가 없을 때는 빈 표에 prod 관측 조건을 설명한다.
